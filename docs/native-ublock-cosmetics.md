# Browser-owned uBlock Origin cosmetic subset

## Architecture and provenance

Argon uses the actual uBlock Origin `AstFilterParser`/`ExtSelectorCompiler` and
`contentscript-extra.js` procedural interpreter from
<https://github.com/gorhill/ublock/tree/3762a26fd65df422080c116e6a70d13bc8d57d62>.
The pinned Firefox manifest reports **1.9.15.101**. This is a commit pin, not a
claim that Argon implements that release's complete behavior.

`argon/adblock/ublock/` contains byte-identical upstream sources, their complete
GPLv3 license, the CSS-tree MIT license, and per-file SHA-256 provenance. The
parser's dependency closure includes `arglist-parser.js`, `jsonpath.js`, and
CSS-tree. `python3 scripts/build-ublock-cosmetics.py` verifies every upstream hash
before reproducing `procedural.js` from `procedural-bootstrap.js` and the complete,
unmodified `contentscript-extra.js`. Tests verify hashes, notices, generated bytes,
and both overlay copy and jar registration.

This is browser-owned integration, **not an extension presented as native**.
The Rust shared library remains the network matcher. The browser service compiles
an additional cosmetic index from the same enabled list/custom-filter generation;
both are published only after the existing durable configuration/cache transaction
succeeds. The native Rust cosmetic response supplies `generichide`; the uBO index
is authoritative for CSS/procedural selection to avoid reintroducing exceptions
through a second cosmetic matcher. No extension messaging/background page is used.

## Delivered and exercised

- Generic CSS selectors, exact and inherited hostname scopes, negated host scopes,
  and matching `#@#` exceptions, selected from enabled lists and the custom editor.
- Real upstream procedural execution; packaged-browser fixtures prove `has-text`,
  `upward`, and `remove`, including dynamically inserted nodes and restoration of
  visibility when a text predicate stops matching.
- Document-scoped Gecko user sheets, including pages with `style-src 'none'`.
  Script CSP is not loosened. Procedural code runs in the actual content window,
  not the parent/system realm or an alternate sandbox global. Only cloned rule
  data and a primitive marker prefix enter the installer; no privileged callback
  is passed. The page callback's Function constructor still throws `EvalError`
  with hash-only script CSP.
- User-sheet CSS is constructed exclusively from parent-selected parser output,
  **never from page-realm return values**. A hostile-page fixture replaces
  `JSON.stringify` to forge CSS; its forged sheet must not take effect.
- Coalesced mutation scheduling (50 ms), upstream per-selector CPU budgets, own
  marker-mutation suppression, pagehide suspension, and pageshow resumption.
  The browser test asserts a genuine `pageshow.persisted` BFCache restoration,
  then verifies procedural filtering resumes after another text mutation.
- Existing trusted top-level site switches, private handling, list transactions,
  and network filtering remain authoritative. The existing packaged-browser suite
  also exercises native cosmetics in cross-host frames and top-level exemptions.

`ArgonAdblock.engine.ublockCosmetics.diagnostics` is a browser-internal report with
`accepted`, `rejected`, reason counts and at most 50 sample raw rules. **Accepted
means indexed, not executed, matched, or proven equivalent to uBO.** This is not a
request logger or per-page blocking counter. Network modifiers are outside this
report; scriptlet/HTML/response-header rules are reported as non-cosmetic extended
rules rather than misrepresented as executable cosmetics.

## Explicitly incomplete

- Entity (`example.*`) and regular-expression host scopes are rejected with an
  `unsupported-host-scope` diagnostic; they are not guessed as hostname suffixes.
- `shadow` is rejected because the page realm cannot provide uBO's closed-root
  extension access. `watch-attr` is rejected because upstream observers would
  also observe Argon's marker writes and schedule loops. Nested occurrences are
  rejected too. Other upstream operators are wired through the real interpreter,
  but only the exercised operators above have packaged-browser acceptance proof.
- Scheduling is coalesced and retains upstream budgets, **not a hard preemption
  guarantee**: a single expensive selector/regex can still take substantial time.
  Main-thread index compilation and broad generic CSS need performance work.
- Installation is at DOMContentLoaded, not an early scriptlet injection system.
  Full `$elemhide`/`$specifichide` semantics, complete browser-context interception,
  redirect resources, scriptlets, response filtering, dynamic filtering, picker,
  logger, migrations and the remaining parity gates are not closed here.
- A page can tamper with its own realm and DOM; isolated-world anti-tampering
  parity is not claimed. No page-controlled data is treated as privileged policy.

Keep the existing uBO installation policy until native-only parity gates pass.
No extension policy was removed by this work.

## Reproduction

```sh
python3 scripts/build-ublock-cosmetics.py
node --test tests/adblock/ublock-cosmetic.test.mjs
python3 scripts/dev-browser.py --sync-only
.cache/browser-venv/bin/python tests/browser/test_ublock_cosmetic.py
npm run test:browser
```

The default browser runner and `npm run test:browser:adblock` include the cosmetic
fixture. It installs no test extension and disables subscription lists for that
fixture to isolate the custom rules. The normal native UI suite separately loads
all 19 shipped list identities. The complete suite also runs the GhostPrint
hash-only-CSP constructor regression.
